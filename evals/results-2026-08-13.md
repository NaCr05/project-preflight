# Forward-Test Results — 2026-08-13

## Method

Three fresh-context agents received the distributable Skill, one realistic user request, and one disposable local repository. They did not receive the expected observations or implementation conclusions. External access was prohibited. The generated state files were then revalidated with `scripts/validate_preflight.py`.

## Results

| Case | Result | Score | Evidence |
|---|---|---:|---|
| Vague agent idea | Pass | 7/7 | Captured the idea, selected `DISCOVERY`, reported missing `grill-me`, preserved all gates, and made no production changes. |
| Existing spec with missing discovery evidence | Pass | 7/7 | Selected the earliest unsupported gate, retained existing spec and tickets as non-authoritative evidence, and refused readiness. |
| Ready project invalidated by API evidence | Pass | 7/7 | Regressed to `DECISION`, invalidated Gates 2–4, retained historical pointers, cleared readiness, and identified the missing `wayfinder` blocker. |

## Deterministic verification

- `DISCOVERY`
- `DISCOVERY`
- `DECISION`

## Self-hosted real-project happy path

After local installation, Project Preflight was applied to the real planning case for Project Preflight v0.1 itself. The active environment exposed all four upstream Skills. The run advanced and validated each state separately:

```text
IDEA
→ DISCOVERY
→ DECISION
→ SPECIFICATION
→ TICKETING
→ READY_FOR_IMPLEMENTATION
```

Durable artifacts included:

- a discovery record covering user, problem, value, inputs, outputs, MVP, non-goals, success criteria, assumptions, and Agent rationale;
- a local Wayfinder map indexing four approved architectural decisions;
- a `to-spec`-shaped specification with fifteen observable user stories and the state-boundary testing seam;
- four local `to-tickets` vertical slices with explicit blockers and an unblocked end-to-end tracer bullet;
- a final state that passed the installed validator at `READY_FOR_IMPLEMENTATION`.

This case scored 7/7 on stage selection, dependency behavior, gate evidence, artifact authority, implementation guardrails, state conformance, and next-action clarity.

## Observed limitation

The isolated evaluators did not expose the locally installed upstream Skill catalog, so the first two fresh-context cases exercised the required missing-dependency path. The self-hosted happy path did expose and follow all installed stage contracts, but it reconstructed already approved user answers and decisions rather than repeating a live `grill-me` interview. A later evaluation should test the complete interactive HITL path with a genuinely unresolved idea and a remote tracker provider.

## Verdict

The v0.1 orchestration, gate ordering, persistence, rollback, dependency failure, production guardrail, and self-hosted local happy path passed the tested scenarios. Interactive HITL and remote-tracker interoperability remain explicit follow-up evaluations.
